# Неделя 5. Проектирование MVP и пользовательских сценариев

## 1. Цель этапа

На пятой неделе команда перешла от теоретической проработки продукта к его структурированию. Основной задачей стало определение минимального набора функций, необходимых для демонстрации ценности продукта.

Цели этапа:
- определить состав MVP
- описать пользовательские сценарии
- сформировать структуру продукта
- подготовиться к разработке

---

## 2. Определение MVP

MVP (Minimum Viable Product) рассматривался как минимальная версия продукта, способная продемонстрировать ключевую ценность.

В рамках проекта было принято решение ограничить функционал следующими возможностями:
- загрузка фото чека
- распознавание и анализ данных с помощью нейросети
- базовая категоризация расходов
- сохранение данных о тратах
- вывод суммы и категорий пользователю
- генерация простых советов по экономии
- сбор статистики трат за неделю / месяц

---

## 3. Выбор платформы для MVP

Было принято решение реализовать MVP в формате Telegram-бота.

Причины выбора:
- высокая скорость разработки
- отсутствие необходимости создавать интерфейс с нуля
- удобство тестирования гипотез
- доступность для целевой аудитории

В качестве следующего шага после проверки гипотез запланирована разработка полноценного мобильного приложения.

---

## 4. Пользовательский сценарий (User Flow)

Базовый сценарий использования Telegram-бота:

1. Пользователь открывает Telegram-бот
2. Отправляет фотографию чека
3. Нейросеть анализирует изображение
4. Система извлекает сумму трат и категории товаров
5. Данные сохраняются в хранилище бота
6. Пользователь получает структурированный ответ с суммой и категориями
7. Система предлагает советы по экономии
8. По запросу пользователь может получить статистику за неделю или месяц

## 6. Ограничения MVP

Сознательно были исключены:
- сложная аналитика и графики
- интеграции с банками
- расширенные отчёты
- персонализация под пользователя
- мобильное приложение (на данном этапе)

Основной фокус — демонстрация базовой ценности через Telegram-бот.
