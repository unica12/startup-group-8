# ЧекМудрец — PWA трекер расходов по фото чека

Курсовой проект РТУ МИРЭА, курс «Стартап в информационных технологиях», группа ЭФБО-06-23, команда №8.
Команда: Земсков А.В., Викторов А.Д., Демидов И.С.
Репозиторий: https://github.com/unica12/startup-group-8
Дедлайн: сжатый (пара дней) — приоритет на рабочий результат, а не на идеальную архитектуру.

Пользователь фотографирует чек → GPT-4o-mini Vision распознаёт товары → траты раскладываются по категориям → приложение показывает статистику и советы по экономии.

Согласованная архитектура — React 19/Vite/Tailwind CSS v4, FastAPI с асинхронным SQLAlchemy, PostgreSQL и Auth в Supabase (`checkmudrets`, Stockholm, eu-north-1). План размещения — FastAPI на Render, PWA на GitHub Pages рядом с лендингом.

## Правила работы

- Весь UI — на русском. Деньги форматируем как `1 234 ₽` (пробел-разделитель тысяч, знак ₽).
- Mobile-first: проверяй вёрстку на ширине 375px. Это PWA, основное использование — с телефона.
- После каждого изменения фронта: `npm run build` в `checkmudrets-pwa/` должен проходить без ошибок.
- Работаем по этапам ниже, по порядку. После каждого этапа — отдельный коммит.
- **Никогда не коммить `.env`** — в `checkmudrets-api/.env` лежит реальный ключ OpenAI. Только `.env.example`.
- Не трогай легаси-папки: `checkmudrets-app/` (старый Flutter) и `checkmudrets-bot/` (старый Telegram-бот, ветки week*). Лендинг живёт в ветке `week14`, папка `docs/` — его тоже не ломать.
- Не выдумывай данные в UI: если у бэкенда нет поля — либо добавь его в API, либо не показывай.
- Если решение неоднозначное (архитектура, хостинг, юр. тексты) — спроси, а не угадывай.

### Frontend (`checkmudrets-pwa/`)
- Навигация без react-router: состояние `page` в `src/App.jsx` + `src/components/BottomNav.jsx` (5 вкладок: Главная, История, Скан, Статистика, Профиль; «Скан» — поднятая круглая кнопка).
- Страницы: `src/pages/{Home,History,Scan,Stats,Profile}.jsx`. Компоненты: `Loader`, `EmptyState`.
- `src/auth/` закрывает основные экраны до восстановления сессии и фиксации согласий. Supabase SDK хранит и обновляет сессию.
- `src/services/supabase.js` использует `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. `src/services/api.js` передаёт Bearer-токен на `VITE_API_URL`. Service worker кэширует файлы приложения, защищённые ответы загружаются с сервера.
- Шрифт Manrope и токены палитры лендинга — в `src/index.css` через `@theme` (Tailwind v4).
- Иконки интерфейса — `lucide-react`. PWA-иконки с маскотом — `public/icons/`.
- `vercel.json` — остаток от старого плана, можно удалить.

### Backend (`checkmudrets-api/`)
- `main.py` — FastAPI, список разрешённых источников CORS из `CORS_ORIGINS`, роутеры auth/receipts/stats/advice/report, `/health`.
- `services/ocr.py` читает чек через GPT Vision и Structured Outputs. `services/receipt_validation.py` проверяет поля и арифметику с `Decimal` и даёт модели конкретные расхождения для одного повтора.
- `services/analytics.py` рассчитывает финансовые инсайты. `services/advisor.py` подбирает практическое действие к факту и кэширует выбор. Короткое наблюдение после сохранения строится по той же истории цен.
- `services/reporter.py` — недельный отчёт с изменением к прошлой неделе.
- `database/models.py` — User(id, auth_user_id UUID unique, name, created_at), ReceiptDraft, Receipt, Item, Consent, AccountDeletion. Внешние ключи чеков и позиций используют прежние целочисленные ID.
- `database/db.py` подключается к PostgreSQL с проверкой сертификата и имени хоста. На старте создаёт таблицы, добавляет недостающий UUID в существующую `users`, включает RLS и отзывает права Data API для прикладных таблиц и их последовательностей. Старые строки остаются в базе без привязки к новым сессиям. SQLite используется для изолированных тестов.
- `services/auth.py` проверяет JWT по JWKS Supabase, включая подпись, issuer, audience, срок действия и `sub`. API привязывает данные к проверенному UUID.
- `utils/config.py` читает `OPENAI_API_KEY`, `OPENAI_MODEL`, `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_DB_CA_FILE`, `SUPABASE_SECRET_KEY`, `CORS_ORIGINS`, `HOST`, `PORT`. Серверный `SUPABASE_SECRET_KEY` включает удаление аккаунта через Supabase Auth. У Session pooler URL проекта определяется из имени пользователя БД, если `SUPABASE_URL` опущен. `SUPABASE_JWT_SECRET` используется только при явной поддержке legacy HS256 на сервере. Для `checkmudrets` JWKS публикует ES256.
- Swagger: `http://localhost:8000/docs` — источник правды по контракту, если этот файл с ним расходится.

## API-контракт (текущий, сверен с `schemas/models.py`)

Для `/auth/me` и его вложенных маршрутов, `/auth/consents`, `/receipts`, `/stats`, `/advice` и `/report` нужен `Authorization: Bearer <access_token>` из Supabase Auth. При отсутствующем, неверном или просроченном токене API возвращает `401`. Для операций с расходами без обязательных согласий API возвращает `403` с кодом `consents_required`.

**GET /auth/me** — идемпотентно создаёт прикладной профиль и возвращает `{ id, name, email, created_at, consents_complete }`. `created_at` берётся из даты регистрации в Supabase Auth. Вход и регистрация выполняются через Supabase Auth.

**PATCH /auth/me** — принимает `{ "name": "Анна Иванова" }`, убирает лишние пробелы, принимает имя длиной от 1 до 80 символов и возвращает обновлённый профиль. Имя хранится в прикладной БД. Метаданные Supabase используются при создании профиля. Смена пароля целиком проходит через Supabase Auth.

**GET /auth/me/stats** — возвращает `{ receipts_count, total_spent, items_count, top_category }` по всем подтверждённым чекам пользователя. Сервер агрегирует деньги в копейках и отдаёт `total_spent` десятичной строкой в рублях. Если положительных расходов по именованным категориям нет, `top_category` равна `null`.

**GET /auth/me/export** — JSON-файл `checkmudrets-export-ГГГГ-ММ-ДД.json` с профилем, всеми подтверждёнными чеками и позициями, записями о согласиях и датой экспорта. Выборка ограничена владельцем из JWT.

**DELETE /auth/me** — останавливает работу с данными аккаунта, удаляет их и вызывает административный API Supabase Auth. Первый запрос требует входа по паролю в последние пять минут. При сбое Admin API возвращается `503`, операция сохраняется и повторяется сервером и по явному запросу. Пока операция ожидает ответа Supabase, остальные защищённые маршруты возвращают `409` с кодом `account_deletion_pending`. После полного удаления ответ `204`, а старый JWT отклоняется на защищённых маршрутах. Для этого сервер сохраняет хеш UUID.

**POST /auth/consents** — принимает `{ "consents": { "terms": "prototype-1", "personal_data": "prototype-1", "cross_border": "prototype-1" } }` и возвращает профиль. Сохраняет тип, версию, дату принятия, IP и User-Agent. Повторная отправка той же версии не дублирует согласия. Неполный или устаревший набор даёт `422`.

**POST /receipts/recognize** — multipart с полем `file`, фото до 12 МБ →
```json
{
  "success": true,
  "draft_id": "cab14bee-77bf-434d-8c3c-4e0e7a478feb",
  "receipt": {
    "store_name": "Демо-магазин", "date": "2026-11-20", "total": "220.02", "discount": null,
    "items": [{ "raw_name": "ЯБЛОКО ГАЛА", "name": "Яблоко Гала", "brand": null, "quantity": "0.384",
                "unit": "кг", "price": "599", "discount": "10", "total": "220.02", "category": "Овощи/Фрукты",
                "package_size": null, "package_unit": null }]
  },
  "retried": false,
  "warnings": [],
  "categories": ["Овощи/Фрукты"],
  "error": null
}
```
`categories` содержит весь список категорий. Неизвестные поля передаются как `null`. Черновик не включён в историю и статистику. При неудачном OCR возвращаются `success: false` и `error`.

**POST /receipts/{draft_id}/confirm** — `{ receipt, accept_warnings: false }` с проверенными полями → `{ receipt: Receipt, mini_advice: Insight | null }`. Поправимые ошибки дают `422`, предупреждения о спорных данных требуют явного принятия через `accept_warnings` (`409` без него). Повторное подтверждение того же черновика возвращает сохранённый чек. Черновик привязан к авторизованному аккаунту.

**GET /receipts?limit=10** → `{ receipts: Receipt[], total_count }`. `total_count` — число чеков в ответе с учётом `limit` от 1 до 100.

**GET /stats?month=YYYY-MM** →
```json
{
  "month": "2026-11", "total_spent": 18420.0, "receipts_count": 15, "average_receipt": 1228.0,
  "by_category": [{ "category": "Продукты", "amount": 8500.0, "percent": 46, "emoji": "🍞" }],
  "largest_purchase": { "name": "Сыр", "amount": 890.0, "category": "Молочные" }
}
```

**GET /advice** → `{ insights: Insight[], empty_message, generated_at }`. `Insight` содержит `type`, `title`, `observation`, `recommendation`, `metric` (`value`, `unit`, `label`), `estimated_savings`, `evidence`, `confidence`. При `?personalize=true` модель подбирает действие из допустимых вариантов к уже рассчитанным фактам. Числа, доказательства и резервные рекомендации формирует Python.

**GET /report** → `{ period: {start, end, label}, total_spent, receipts_count, change_pct, change_text, top_categories: [{category, amount, emoji}], summary_text }`

Категории OCR: Продукты, Молочные, Мясо, Овощи/Фрукты, Хлеб, Напитки, Алкоголь, Кофе, Сладости, Снеки, Готовая еда, Бытовая химия, Гигиена, Косметика, Одежда, Электроника, Лекарства, Транспорт, Топливо, Другое. Эмодзи — `utils/formatting.py::CATEGORY_EMOJI`.

### Известные проблемы бэкенда
- Статистика и отчёт относят подтверждённый чек к дате покупки, если она указана. Старые чеки и чеки без даты сохраняют прежний учёт по дате сканирования. Сравнения цен и другие инсайты по периодам используют только известную дату покупки.
- OpenAI API блокирует запросы с российских IP → бэкенд нельзя хостить на российском сервере без прокси.

- [x] Миграция PostgreSQL применяется при запуске API в транзакции. Она добавляет поля и таблицу черновиков к существующей схеме, оставляет старые строки и значения без изменений и включает RLS. Проверена повторная миграция локальной копии схемы Этапа 2. Для автоматизированных тестов используется новая изолированная SQLite.
- [x] Аналитика покрывает сравнение магазинов, изменение цены, цену за кг/л, покупательские привычки, сопоставимые периоды, вклад категорий в рост, прогноз и оценку экономии. Карточки на главной и в статистике появляются по мере накопления данных.
- [x] GPT выбирает практическое действие из вариантов для рассчитанного факта. Результат кэшируется в процессе API по аккаунту и набору фактов. Главная получает расчёты без запроса к GPT. Подсказка после сохранения появляется при наличии сопоставимой недавней цены.
- [x] Пройдены тесты FastAPI, сборка и линтер. В Chromium на 375 px проверены сверка, повтор, редактирование, сохранение и аналитика. На искусственном чеке проверен ответ GPT-4o-mini с весовой позицией и скидками.

Сравнения цен используют последние 90 дней и совпадение названия, бренда и характеристик. Для явно названных сортов весовых овощей и фруктов бренд может отсутствовать. Сравнение магазинов и оценка экономии опираются на цены за последние 30 дней с разницей между наблюдениями не более 14 дней. Цены относятся к соответствующим чекам, оценка экономии показывает, какой могла бы быть разница для фактического объёма покупок. Чеки с неразнесённой общей скидкой или подтверждённым расхождением исключаются из сравнения цен и категорий. Старые чеки без единиц и характеристик участвуют в общей истории расходов.

Для категорий сравниваются два отрезка по 30 завершённых календарных дней. Нужны чеки минимум за три разных дня в каждом отрезке с охватом не менее 14 дней. Прогноз требует истории прошлого месяца и минимум 10 полных дней текущего месяца. Его точность зависит от того, насколько регулярно добавляются чеки.

## Настройки Supabase Dashboard

1. В проекте `checkmudrets` открой **Connect** и скопируй Project URL. Добавь его в `checkmudrets-pwa/.env` как `VITE_SUPABASE_URL`. В **Project Settings → API Keys → Publishable key** возьми `sb_publishable_…` для `VITE_SUPABASE_PUBLISHABLE_KEY`. [API keys](https://supabase.com/docs/guides/getting-started/api-keys)
2. В **Connect → Session pooler** скопируй строку подключения с портом `5432` в `checkmudrets-api/.env` как `DATABASE_URL`. Замени весь плейсхолдер пароля вместе со скобками. Специальные символы пароля в URI должны быть URL-кодированы. В **Database → Settings → SSL Configuration → Download certificate** скачай сертификат и укажи локальный путь в `SUPABASE_DB_CA_FILE`. [Postgres и SSL](https://supabase.com/docs/guides/database/connecting-to-postgres)
3. В **Authentication → Sign In / Providers** оставь включённым Allow new users to sign up. В разделе **Email** включи Email и Confirm Email. В **Authentication → URL Configuration** установи Site URL `http://localhost:5173/` для локальной демонстрации и добавь этот же точный адрес в Redirect URLs. Если открываешь PWA по `http://127.0.0.1:5173/`, добавь и этот адрес. Адрес GitHub Pages добавляется на Этапе 4. [Настройки Auth](https://supabase.com/docs/guides/auth/general-configuration)
4. Для проверки письма в облачном проекте используй адрес участника команды проекта. Для демонстрации регистрации на сторонние адреса настрой **Authentication → SMTP Settings**. Встроенная отправка ограничена адресами участников команды. [Настройка SMTP](https://supabase.com/docs/guides/auth/auth-smtp)
5. Если проект используется только ЧекМудрецом, можно отключить весь Data API через **Integrations → Data API → Enable Data API**. Прикладные таблицы уже закрыты правами и RLS при запуске FastAPI. [Доступ к таблицам](https://supabase.com/docs/guides/api/securing-your-api)
6. Для удаления аккаунтов создай отдельный ключ в **Project Settings → API Keys → Secret keys**. Добавь значение `sb_secret_…` как `SUPABASE_SECRET_KEY` в `checkmudrets-api/.env` и в окружение Render при развёртывании. Перезапусти API. Publishable key используется в PWA. [Ключи Supabase](https://supabase.com/docs/guides/getting-started/api-keys)
7. Для дополнительной серверной проверки смены пароля в Email-настройках Auth можно включить **Require current password when changing password**. PWA уже повторно проверяет текущий пароль и передаёт его Supabase при смене. [Проверка пароля в Supabase](https://supabase.com/docs/guides/auth/password-security)

## Команды
Выполни команды в двух терминалах из корня репозитория. Для фронтенда нужен Node.js 22.12+.

```bash
# Backend (Python 3.13)
cd checkmudrets-api
uv venv --python 3.13 .venv
uv pip install --python .venv/bin/python -r requirements.txt
test -f .env || cp .env.example .env
# Заполни OPENAI_API_KEY, DATABASE_URL и путь к CA в .env. Для удаления задай SUPABASE_SECRET_KEY.
.venv/bin/python -m uvicorn main:app --reload   # http://localhost:8000/docs
```

```bash
# Frontend
cd checkmudrets-pwa
npm ci
test -f .env || cp .env.example .env
# Заполни URL и publishable key Supabase в .env.
VITE_API_URL=http://localhost:8000 npm run dev -- --strictPort   # http://localhost:5173
npm run build
npm run lint
```

Для локальной проверки собранной PWA используй `npm run build -- --mode development` и `npm run preview` с локальными настройками. Обычная сборка `npm run build` включает адрес API только при заданном публичном HTTPS URL. Без него PWA показывает сообщение о настройке подключения.

Автотесты FastAPI создают временную SQLite и локальный JWKS. Они проверяют JWT и ротацию ключей, согласия, профиль, статистику за всё время, экспорт и изоляцию его данных, повтор удаления после сбоя, проверку OCR и повтор, подтверждение, отсутствие дубликатов и расчёт инсайтов. Внешние ответы OpenAI подменяются в автотестах.

```bash
cd checkmudrets-api
uv pip install --python .venv/bin/python -r requirements-test.txt
.venv/bin/python -m unittest discover -s tests -v
```

Vite слушает локальную сеть. Для проверки с телефона укажи адрес API, доступный с телефона. Для проверки камеры и установки PWA используй HTTPS или localhost.
